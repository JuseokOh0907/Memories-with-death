# 구현 기획 — 영혼(기억) · 시점 전환 · 지역 페이드

2026-11-05 논의 정리. 아직 구현하지 않았다. 확정된 영혼 동작은 [`../decisions/003-soul.md`](../decisions/003-soul.md),
맵 구조는 [`../decisions/004-map-structure.md`](../decisions/004-map-structure.md).

**선행 조건:** 영혼이 실제로 무엇을 하는지(마법 종류)는 컨셉 문서(Codex 에서 작업 후 전달)를 받은 뒤 정한다.
아래 3·4 절의 "약화" 와 "마법" 은 그때 구체화한다.

---

## 1. 설정 — 영혼은 플레이어의 기억이다

- 영혼은 플레이어의 **기억**이며, 마법은 영체(영혼) 기준으로 쓴다.
- **몸이 들어가 본 곳에만 영혼이 들어갈 수 있다.** 탐험은 몸이, 활용은 기억이 한다.
- 영혼은 새 곳을 밝히지 않는다. (기각: "영혼으로 정찰해 지도를 먼저 공개" — 설정과 충돌)

## 2. 방문한 방 — 데이터 하나가 세 역할

```
방문한 방 목록 (Room ID 집합)
  ├─ 지도   방문한 방이 지도에 그려진다
  ├─ 영혼   방문한 방 안으로만 이동할 수 있다
  └─ 저장   이 목록이 곧 진행도
```

- 단위는 `Room` (지도 한 칸). 방에 한 발이라도 들어가면 방 전체를 기억한다.
- 기록 지점: `PlayerRoomTracker.RoomChanged` — 새 방에 들어갈 때 목록에 추가.
- 저장 형식에 포함 (인계 문서 §8 저장 대상에 "방문한 방" 추가).
- Room ID 는 세계 전체에서 유일해야 한다 (파츠 이름 접두사, 결정 004).

### 영혼 이동 제한 (구현 1순위 — 작은 변경)

현재 조건(반경 `maxDistance` · 화면 안)에 **"클릭 지점이 방문한 방 안"** 을 더한다.

- 클릭 지점이 들어 있는 `Room` 을 찾는다 (방 트리거에 대한 점 검사 또는 방 목록 조회).
- 방문하지 않은 방이면 이동하지 않는다. 피드백(작은 거부 표시)을 함께 준다.
- 가는 길이 방문하지 않은 방을 지나가는 경우는 허용할지 정해야 한다 — 영혼은 벽을 통과하므로
  "목표 지점만 검사" 가 단순하다. 플레이해 보고 결정.
- 영혼이 머무는 방이 어떤 이유로 미방문 상태가 되는 일은 없다 (방문 기록은 지워지지 않는다).

## 3. 거리 3구간 — 자동 귀환 대신 능력 한계

| 구간 | 영혼 상태 | 표시 |
|---|---|---|
| 가까움 | 모든 마법 사용 | 기본 |
| 멀어짐 | 이동·관찰만, 마법 약화 또는 불가 | 영혼이 흐려짐 · 연결선 색 변화 |
| 한계 | 플레이어에게 다시 붙음 (현재 구현) | — |

- 지금은 "한계" 하나뿐이라 경고 없이 붙는다. 가운데 구간이 경고 역할을 한다.
- 거리 한계 자체를 **성장 요소**로 — 능력을 얻을 때마다 닿는 거리가 늘어난다 (진행 게이트).
- "기억은 있지만 너무 멀다" 상황이 생겨 몸의 위치가 계속 중요하다.

## 4. 호출 규칙

| 방식 | 역할 | 상태 |
|---|---|---|
| 우클릭 호출 | 플레이어 편의 | 구현됨 |
| 한계 거리 이탈 시 재부착 | 안전장치 | 구현됨 |
| **강제 호출 기믹** | 레벨·스토리 통제 | 미구현 |

강제 호출 기믹 예:

- **영혼 차단 결계** — 영혼이 지날 수 없는 구역. 몸만 가는 길 / 영혼만 닿는 곳을 나눈다.
- **스토리 연출** — 영혼(기억)이 무언가에 끌려가거나 끌려오는 장면.

## 5. 시점 전환 — 카메라 두 대, 페이드 없음

```
Main Camera   플레이어를 따라감 (큰 화면)
Soul Camera   영혼을 따라감 (작은 창)
전환 키       두 카메라의 화면 영역(viewport rect)만 맞바꾼다. 즉시, 페이드 없음
```

- 같은 씬의 이어진 세계라 두 시점 모두 이미 렌더링 가능하다. 불러오기가 없다.
- 작은 창에 본체가 계속 보여 **몸·영혼 동시 조작**이 유지된다 (타이밍 퍼즐).
- 전환 표시는 페이드 대신 색감 변화·테두리 효과처럼 가볍게.
- **해금 시점:** 처음부터가 아니라 중반 능력으로 — 백트래킹 시 옛 지역에 새 풀이를 준다.

구현 시 확인할 것:

1. **클릭 판정** — 커서가 어느 카메라 화면 안인지(`Camera.pixelRect`) 보고 그 카메라로 월드 좌표를 구한다.
   지금 `SoulController` 는 카메라 하나(`worldCamera`) 만 쓴다.
2. **영혼 이동 범위** — 지금은 "메인 화면 안". 영혼 시점에서는 영혼 카메라 기준으로 다시 잡는다.
3. **Soul Camera 의 경계** — 영혼이 있는 방의 범위. 영혼에도 현재 방 추적이 필요하다.
4. **작은 창 크기** — 1280×720 에서 영혼 주변이 읽혀야 한다 (인계 문서 §5.3 해상도 확인).
5. 카메라 두 대 렌더링 비용 — 2D 라 작지만 실제 기기에서 확인.

## 6. 페이드 — 지역 이동에만

- 지역 안의 방 사이는 **이어서 걷는다** (카메라가 새 방 범위로 부드럽게 넘어감).
- 페이드는 **큰 지역(다른 동화 세계 등) 사이 이동**과 **리스폰**에만. 지역 이동은 씬 로드를 동반하므로 자연스럽다.
- 페이드는 `Time.timeScale` 과 무관한 시계(unscaled)로 돌린다 — 일시정지와 겹쳐도 멈추지 않게.
  시간 배율 관리 원칙은 [`../BACKLOG.md`](../BACKLOG.md) 슬로우 모션 항목과 같다.

## 7. 검토 중 (컨셉 문서 이후 판단)

- **기억 속 모습** — 영혼 시점이 현재가 아니라 몸이 처음 지나갈 때의 모습을 보여 준다
  (그때는 열려 있던 문 등). "기억과 현재가 다르다" 퍼즐 · 스토리와 직결. 방마다 상태 스냅샷이 필요해 비용이 크다.

## 구현 순서 (제안)

1. 방문한 방 기록 (`PlayerRoomTracker`) + 디버그 표시
2. 영혼 이동 제한: 방문한 방 안만
3. 거리 3구간 표시 (흐려짐·연결선) — 마법이 정해지면 약화 규칙
4. 강제 호출 기믹 (결계 트리거)
5. 저장에 방문한 방 포함 (4일차 로컬 저장과 함께)
6. 시점 전환 카메라 (해금 능력과 함께)
7. 지역 페이드 (두 번째 지역이 생길 때)
