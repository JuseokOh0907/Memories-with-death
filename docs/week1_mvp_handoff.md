# Claude Code 개발 인계 — 잔혹동화 메트로배니아 1주차 MVP

작성일: 2026-10-26 (한국 시간)

## 1. 이번 작업의 목적

임시 그래픽과 임시 맵으로 실제 플레이 가능한 2D 횡스크롤 액션 탐험 프로토타입을 완성한다. 전체 제작 목표 기간은 1개월이다. 첫 주에는 스토리나 최종 아트보다 이동·점프·전투·능력 획득·재탐험·UI의 연결을 검증한다.

핵심 플레이 흐름:

> 이동과 점프 학습 → 막힌 길 발견 → 다른 경로 탐험 및 전투 → 공중 대시 획득 → 이전 공간 재방문 → 새로운 길 통과 → 도착 지점

목표 플레이 시간은 처음 접하는 플레이어 기준 약 10~15분이다. 짧은 테스트 구간을 불필요하게 늘려 이 시간을 맞추지는 않는다.

## 2. 프로젝트 배경과 확정 범위

- 장르: 2D 횡스크롤 액션 탐험 / 메트로배니아.
- 장기 테마: 여러 국가의 고전 동화와 잔혹한 원전 요소를 활용한 세계.
- 주인공 방향: 동화 원작 인물이 아닌 제3의 조력자로서 탈출구를 찾는 구상. 정체성·외형·세부 스토리는 추후 확정한다.
- 장기 구조: 동화 세계의 방문 순서는 유연하게 하고, 개별 동화의 주요 사건은 인과관계를 유지한다. 다른 세계에서 얻은 능력으로 새로운 접근 경로를 연다.
- 능력은 지역을 떠나도 유지된다. 능력 부족 상태로 돌아올 수 없는 지역에 갇히는 진행 불가 상황을 만들지 않는다.
- 이번 주에는 동화 시나리오, 마녀 보스, 제작 시스템, 여러 동화 세계를 구현하지 않는다.
- 이번 주 공중 대시는 탐험 구조 검증용 임시 능력이다. 최종 능력의 이름·연출·설정으로 확정하지 않는다.
- 맵, 캐릭터, 적은 도형 및 단색 타일로 제작한다. 최종 애니메이션·이펙트·사운드는 이후 교체한다.

## 3. Claude Code 작업 시작 지침

1. 실제 구현 대상 저장소의 AGENTS.md 및 기존 프로젝트 구조를 먼저 확인한다.
2. 엔진·버전·입력 시스템·실행 방법을 확인하고 기존 구성을 우선 사용한다. 이번 문서를 작성한 C:\GameMake에는 게임 엔진 프로젝트가 확인되지 않았다. 이 폴더가 구현 저장소라고 가정하지 않는다.
3. 엔진이 정해져 있지 않고 새 프로젝트를 만들어야 한다면 엔진과 프로젝트 경로를 사용자에게 확인한 뒤 시작한다. Unity, Godot, 웹 중 하나를 임의로 확정하지 않는다.
4. 아래 수치와 키 배치는 초기 제안값이며 플레이 테스트로 조정할 수 있다. 변경 이유와 최종값을 기록한다.
5. 매일 실행 가능한 상태를 유지한다. 큰 프레임워크나 아직 필요 없는 범용 기능을 먼저 만들지 않는다.
6. 실행하지 못한 검증을 통과했다고 보고하지 않는다. 구현 완료와 실제 플레이 검증 완료를 구분한다.

## 4. 첫 주차 필수 구현 사양

### 4.1 캐릭터 이동과 충돌

- 좌우 이동 및 바라보는 방향 변경. 지상에서는 빠르게 가속·정지한다.
- 지상, 상승, 하강, 대시, 피격, 사망 상태가 충돌하지 않도록 동작을 구분한다.
- 공중 방향 조절을 지원한다. 상승과 하강을 예측할 수 있어야 한다.
- 벽·바닥·천장 충돌을 처리하고 착지·천장 충돌 시 수직 속도를 적절히 정리한다.
- 캐릭터 표시 이미지와 물리 충돌체를 분리하여 추후 아트 교체가 이동 판정에 영향을 주지 않게 한다.
- 입력 읽기와 물리 갱신을 엔진의 적절한 주기에 배치한다. 프레임 수에 따라 이동 거리가 크게 달라지지 않게 한다.
- 이동 발판, 경사면, 벽타기, 벽점프, 사다리, 수중 이동은 이번 주 범위에서 제외한다.

### 4.2 점프

- 누르는 시간에 따른 가변 높이 점프. 버튼을 빨리 놓으면 상승이 짧아진다.
- 코요테 타임: 발판을 벗어난 직후 약 0.10초 동안 점프 허용.
- 입력 버퍼: 착지 약 0.10초 전의 점프 입력을 기억해 착지 시 실행.
- 상승보다 하강이 약간 빠른 감각으로 시작하되 수치 조정 가능.
- 천장에 부딪히면 상승을 중단한다. 점프를 길게 누른 상태에서 착지해도 자동 연속 점프하지 않는다.
- 기본 상태에서는 이단 점프를 제공하지 않는다.

### 4.3 공중 대시 — 획득 능력

- 획득 이전에는 사용할 수 없고, 획득 이후에는 저장·재시작·지역 이동 후에도 유지한다.
- 공중에서 수평으로 한 번 사용 가능하며 착지하면 충전된다.
- 방향 입력이 있으면 해당 방향, 없으면 바라보는 방향으로 사용한다.
- 지상에서는 발동하지 않는 것으로 첫 버전을 통일한다. 추후 지상 대시는 별도 판단한다.
- 초기 지속 시간은 약 0.15초. 속도와 이동 거리는 테스트 지형에 맞춰 조정한다.
- 대시 중 중력 적용 방식과 종료 후 속도를 명시적으로 처리하여 과도한 부양이나 급격한 낙하를 막는다.
- 벽을 통과하지 않으며, 막히면 안전하게 멈춘다. 빠른 이동으로 얇은 충돌체를 관통하지 않는지 검증한다.
- 첫 버전에는 대시 무적을 넣지 않는다. 피격되면 대시를 취소하고 피격 상태로 전환한다.
- 획득 직후 추락 위험이 낮은 공간에서 연습할 수 있게 한다.

### 4.4 기본 공격과 피격

- 전방 근접 공격 1종. 지상·공중 모두 사용한다.
- 공격 준비·유효 판정·회복 시간을 조정 가능한 값으로 분리한다.
- 공격 1회에서 동일 적에게 피해가 중복 적용되지 않는다.
- 공격 버튼을 누르고 있다고 매 프레임 공격하지 않도록 재공격 조건을 둔다.
- 공격 중 공중 이동과 중력은 유지한다. 대시 중 공격 입력은 첫 버전에서 무시한다.
- 피해를 받으면 체력 감소, 짧은 무적, 제한적인 밀려남을 적용한다. 연속 접촉으로 즉시 체력이 모두 소진되지 않게 한다.
- 피격 무적 초기값은 약 0.7초. 피격으로 현재 공격을 취소한다.
- 체력 0이면 입력 및 공격 판정을 중단하고 사망 UI를 표시한다.
- 보스, 패링, 콤보, 원거리 공격, 속성 피해는 제외한다.

### 4.5 초기 스테이터스

| 항목 | 초기값 또는 규칙 |
|---|---|
| 최대 체력 | 5 |
| 현재 체력 | 시작 및 체크포인트 재시작 시 최대치 |
| 기본 공격력 | 1 |
| 일반 적 체력 | 2~3, 테스트로 조정 |
| 적의 공격 피해 | 1 |
| 이동 속도·점프 높이 | 엔진 단위에 맞게 조정 가능한 설정값으로 관리 |
| 능력 소유 여부 | 공중 대시 잠김 / 획득 |
| 대시 사용 가능 여부 | 소유 여부와 별개인 일시 상태 |

경험치, 레벨, 스탯 포인트, 장비 등급, 마나, 스태미나, 재화는 이번 주에 넣지 않는다. HUD와 스테이터스 창은 실제 게임 상태를 읽고, 각각 별도의 체력 값을 관리하지 않는다.

## 5. 필수 UI

### 5.1 플레이 HUD

- 화면 좌상단: 현재/최대 체력. 숫자 또는 체력 칸으로 명확하게 표시.
- 능력 표시: 대시 획득 전에는 잠김, 획득 후에는 사용 가능/공중 사용 완료 상태 구분. 색상만으로 구분하지 않고 문자나 형태를 함께 사용.
- 상호작용 대상 근처: 행동명과 키 안내. 동시에 여러 대상의 안내가 겹치지 않게 가장 가까운 유효 대상을 선택.
- 최초 조작 안내: 이동, 점프, 공격, 상호작용을 필요한 위치에서 짧게 표시.
- 획득 알림: 능력 이름, 조작키, 핵심 규칙. 확인하면 닫히고 중복 지급되지 않음.
- 체크포인트 활성화 알림.
- 도착 지점: 프로토타입 완료 안내 및 다시 시작 선택.

### 5.2 스테이터스 창

- Tab으로 열고 닫는다. 열려 있는 동안 게임을 일시정지한다.
- 표시 항목: 임시 캐릭터명, 현재/최대 체력, 공격력, 획득 능력과 설명, 현재 체크포인트, 조작 안내.
- 미획득 대시는 잠긴 능력으로 표시한다. 가상의 장비 슬롯이나 작동하지 않는 스탯 상승 버튼은 만들지 않는다.
- 읽기 전용 창으로 시작한다. 닫기 버튼과 Esc 지원.
- 창이 열린 동안 이동·점프·공격·상호작용 입력이 게임에 전달되지 않아야 한다.

### 5.3 일시정지 및 사망 UI

- Esc: 일시정지 메뉴. 계속하기, 체크포인트에서 재시작, 종료 제공.
- 체크포인트 재시작에는 확인 단계를 둔다. 획득 능력과 영구 개방 통로는 유지한다.
- 사망 화면: 체크포인트에서 재시작 버튼. 사망 상태에서 스테이터스 창을 열어 게임을 재개하지 못하게 한다.
- 스테이터스·획득 안내·일시정지 메뉴가 중복으로 열리지 않게 한다. Esc는 최상위 창을 닫는 것으로 일관되게 처리한다.
- UI 정지 중 물리·적·공격 타이머가 멈추고, UI 자체는 정상 동작해야 한다.
- 창을 닫을 때 누르고 있던 버튼 때문에 공격이나 점프가 의도치 않게 실행되지 않게 한다.
- 1280×720 및 1920×1080에서 텍스트와 버튼이 잘리지 않는지 확인한다.

### 5.4 키보드 기본 조작 제안

| 행동 | 키 |
|---|---|
| 좌우 이동 | A/D 또는 좌우 방향키 |
| 점프 | Space |
| 근접 공격 | J |
| 공중 대시 | K 또는 Left Shift |
| 상호작용 | E |
| 스테이터스 창 | Tab |
| 일시정지 / 열린 창 닫기 | Esc |

키를 여러 스크립트에 직접 분산하지 않고 입력 액션으로 관리한다. 게임패드 및 키 변경 UI는 기존 프로젝트에 지원이 있을 때 활용하고, 신규 지원은 1주차 필수 범위에서 제외한다.

## 6. 카메라와 최소 피드백

- 카메라는 캐릭터를 부드럽게 추적하며 방 또는 맵 경계를 벗어나지 않는다.
- 이동 방향의 앞 공간과 착지할 바닥이 보이도록 화면 구도를 조정한다.
- 작은 점프마다 화면이 과도하게 출렁이지 않게 수직 추적 범위를 조정한다.
- 리스폰 시 카메라를 즉시 올바른 위치로 옮긴다. 사망 위치에서 재시작 위치까지 천천히 날아가지 않게 한다.
- 적 명중·캐릭터 피격·능력 획득을 단색 점멸, 간단한 도형, UI 텍스트로 구분한다.
- 짧은 타격 정지는 선택 사항이며, 적용한다면 일시정지/사망과 충돌하거나 게임 속도가 복구되지 않는 문제가 없어야 한다.
- 최종 사운드와 아트는 필요 없지만 공격 적중과 피해 발생을 플레이어가 구분할 수 있어야 한다.

## 7. 임시 맵 및 적 구성

약 6개의 작은 구역을 하나의 임시 레벨 안에 구성해도 된다. 실제 씬을 6개로 분리하는 것은 요구사항이 아니다.

```text
[시작·체크포인트] ─ [갈림길] ─ [대시 필요 틈] ─ [도착 지점]
                       │
                  [점프·전투 구간]
                       │
                  [대시 획득 구간]
                       │
                  [갈림길로 돌아오는 지름길]
```

- 기본 점프와 최대 코요테 점프로는 대시 필요 틈을 넘을 수 없어야 한다.
- 대시를 이용하면 숙련자만 가능한 한계 점프가 아니라 여유 있게 통과할 수 있어야 한다.
- 획득 후 지름길을 열어 돌아오는 길의 반복 이동을 줄인다.
- 지름길은 반대편에서 먼저 열어 능력 구간을 건너뛰는 일이 없도록 확인한다.
- 낭떠러지 또는 위험 구역은 체력 1을 차감하고 근처의 사전에 지정한 안전 위치로 복귀시킨다. 체력이 0이면 일반 사망 흐름을 따른다. 복귀 위치가 다시 낙사를 유발하지 않아야 한다.
- 필수 진행 경로에 보이지 않는 낙하 착지나 정밀한 픽셀 단위 점프를 요구하지 않는다.
- 일반 적 2종: 지상 순찰형, 예고 후 돌진형. 순찰형은 발판 끝에서 돌아서고, 돌진형은 예고·돌진·회복 상태를 구분한다.
- 적의 접촉 피해와 공격 판정은 한 번의 접촉에서 중복 피해를 발생시키지 않는다.
- 미니맵과 월드맵 UI는 제외한다. 갈림길을 적게 만들고 지형·표식으로 기억할 수 있도록 한다.

## 8. 체크포인트와 저장

- 체크포인트 상호작용 시 위치 저장 및 체력 회복.
- 사망 시 마지막 체크포인트에서 최대 체력으로 재시작.
- 능력 획득, 영구 지름길 개방, 체크포인트 갱신 시 로컬 저장.
- 저장 대상: 저장 형식 버전, 마지막 체크포인트 ID, 획득 능력, 영구 개방 상태.
- 적의 현재 위치, 공격 타이머, 사용 중인 대시 등 일시 상태는 저장하지 않는다.
- 재시작 또는 재실행 시 일반 적은 초기 상태로 복구하고 플레이어 일시 상태를 초기화한다.
- 획득 능력과 열린 지름길은 사망·재실행 후에도 유지하며 능력 아이템은 다시 생성하지 않는다.
- 저장 파일이 없으면 새 게임. 손상되었거나 지원하지 않는 저장 형식이면 오류 안내와 새 게임 선택을 제공한다. 조용히 기존 저장을 덮어쓰지 않는다.
- 테스트용 저장 초기화 기능은 개발용 메뉴에 두고 확인 후 실행한다.
- 클라우드 저장, 다중 슬롯, 전체 게임 상태 직렬화는 제외한다.

## 9. 구조와 디버그 원칙

캐릭터 동작, 체력·피해, 능력 소유 상태, 진행 저장, UI 표시, 카메라를 역할별로 분리한다. 엔진의 기존 컴포넌트나 프로젝트 패턴을 활용하고 불필요한 추상화는 피한다.

이동 속도, 가속/감속, 점프, 중력, 입력 보정 시간, 대시, 공격, 무적 시간은 한눈에 찾을 수 있는 설정 위치에 둔다. 최종 그래픽 교체로 물리 설정이 바뀌지 않게 한다.

개발용 디버그 표시에는 캐릭터 상태, 접지 여부, 속도, 대시 소유/사용 여부, 체력, 체크포인트 ID를 포함한다. 충돌체와 공격 범위를 확인할 수 있게 한다. 디버그 기능은 정상 플레이에서 끌 수 있어야 한다.

## 10. 첫 주차 일정과 일별 완료 기준

착수일부터 작업일 5일 기준이다. 날짜가 아니라 실제 검증 결과로 완료를 판단한다.

| 작업일 | 목표 | 당일 완료 기준 |
|---|---|---|
| 1일차 | 실행 환경, 입력, 좌우 이동, 기본 점프, 카메라 | 테스트 바닥에서 이동·점프·벽/천장 충돌이 동작하고 실행 방법이 기록됨 |
| 2일차 | 가변 점프, 입력 보정, 임시 맵, 낙사 복귀, 체크포인트 | 점프 테스트 구간을 반복 통과할 수 있고 낙사 후 정상 복귀함 |
| 3일차 | 공격·피격·사망, 일반 적 2종, 체력 HUD | 적을 처치할 수 있고 피해·무적·사망·재시작이 일관되게 동작함 |
| 4일차 | 대시 획득, 재탐험 경로, 스테이터스/일시정지 UI, 로컬 저장 | 능력 획득 후 막힌 길을 통과하고 재실행해도 진행이 보존됨 |
| 5일차 | 전체 플레이 테스트, 조작감 조정, 버그 수정, 실행물 정리 | 새 게임부터 도착까지 통과하고 아래 필수 검증표와 인계 자료를 완료함 |

UI는 마지막에 몰아서 붙이지 않고 체력·능력·저장 상태가 구현되는 날 함께 연결한다. 일정이 밀리면 장식, 타격 정지, 선택 콘텐츠를 먼저 줄이고 이동·능력·재시작·UI 안정성은 유지한다.

## 11. 1주차 최종 검증표

### 조작과 전투

- [ ] 짧은 점프와 긴 점프의 높이가 명확히 다르다.
- [ ] 발판 이탈 직후 점프와 착지 직전 입력이 의도대로 동작한다.
- [ ] 점프 버튼 유지로 자동 재점프하지 않는다.
- [ ] 벽·천장·모서리에서 끼임, 무한 접지, 대시 관통이 발생하지 않는다.
- [ ] 공격 1회가 동일 적에게 중복 피해를 주지 않는다.
- [ ] 연속 접촉 피해에 무적 시간이 적용되고 사망 후 공격할 수 없다.
- [ ] 30/60/120 FPS 제한 환경에서 이동·점프·대시 거리가 진행 난이도를 바꿀 만큼 달라지지 않는다.

### 탐험과 진행

- [ ] 새 게임에서 대시를 사용할 수 없다.
- [ ] 기본 점프로는 막힌 길을 통과할 수 없으며 대시 획득 후에는 통과할 수 있다.
- [ ] 능력 획득 후 플레이어가 돌아갈 장소를 인식할 수 있다.
- [ ] 지름길이 실제 복귀 이동을 단축하고 진행 순서를 의도치 않게 건너뛰지 않는다.
- [ ] 낙사·사망·재시작·프로그램 재실행 후에도 진행 불가 상태가 없다.
- [ ] 저장된 능력·체크포인트·지름길 상태가 재실행 후 복구된다.

### UI와 사용성

- [ ] HUD와 스테이터스 창의 체력·능력 표시가 실제 상태와 일치한다.
- [ ] 일시정지·스테이터스·획득 안내·사망 화면의 중복 표시나 입력 누출이 없다.
- [ ] 정지 중 적·물리·타이머는 멈추고 메뉴는 조작 가능하다.
- [ ] 창을 닫은 뒤 게임 속도와 입력이 정상 복구된다.
- [ ] 1280×720 및 1920×1080에서 UI가 잘리지 않는다.
- [ ] 설명 없이도 첫 플레이어가 기본 조작과 다음 탐험 방향을 이해한다.

자동 검증은 피해 중복 방지, 능력 저장 복원 등 회귀 위험이 있는 핵심 로직에 집중한다. 조작감·카메라·탐험 가독성은 직접 플레이로 확인하고, 사용자 플레이 테스트가 필요하면 미검증 상태로 명확히 남긴다.

**첫 주차 완료 정의:** 임시 그래픽 상태에서 새 게임을 시작하여 이동·전투·대시 획득·재탐험·도착까지 플레이할 수 있고, HUD와 스테이터스 창 및 체크포인트/저장이 이 흐름과 함께 정상 동작한다. 단순히 기능별 코드가 존재하는 상태는 완료로 보지 않는다.
