# 002 — 공격 우선순위와 점프 정점

2026-10-26 확정.

## 1. 공격은 이동 상태를 기다리지 않는다

- 지상·상승·하강 어디서든 공격 입력이 들어온 **그 물리 스텝에** 공격이 시작된다.
  막는 상태는 대시·피격·사망뿐이다.
- 입력 처리는 `PlayerController` 가 한다 (상태 확인 → `PlayerCombat` 시작 → 상승 중이면 정점 처리).
  `PlayerCombat` 은 이동을 모르고 공격 타이머와 스윙당 맞은 대상만 다룬다.

## 2. 상승 중 공격 지점이 최고 높이가 된다

- 상승 중에 공격하면 수직 속도를 **0** 으로 만든다 → 다음 스텝에 하강으로 넘어간다.
  공격 모션이 끝나면 항상 하강 중이므로 **낙하 모션으로 이어진다.**
  "상승 중인데 점프 모션이 아닌" 경우가 생기지 않는다.
- 하강 중·지상 공격은 속도를 건드리지 않는다.
- 기각: "정점 근처에서만 공중 공격 허용" — 그 밖의 입력을 버리거나 미루게 되어
  점프 중 공격이 늦게 나가는 원래 문제가 되살아난다.
- 인계 문서 §4.4 "공격 중 중력 유지" 와의 차이: 시작 순간 **상승 속도만** 0 으로 만들고
  그 뒤 중력·수평 이동은 그대로 유지한다.

## 3. 정점 구간 중력 (공격 여부와 무관)

- 점프로 뜬 공중에서 `|수직 속도| < apexSpeedThreshold` 이면 중력에 `apexGravityMultiplier` 를 곱한다.
  최고점에서 잠깐 머무는 일반적인 플랫포머 방식이다.
- 공중 공격은 속도를 0 으로 만들므로 **같은 정점 구간에 자연스럽게 들어온다.** 별도 처리 없음.
- 걸어서 떨어질 때와 천장에 부딪힌 뒤에는 쓰지 않는다 (모서리·천장에서 떠 있는 느낌 방지).
- 우선순위: 정점 배율 > 하강 배율 > 기본 중력.

## 4. 하강 중력 — 미정

지금은 `fallGravityMultiplier` 고정 배율(1.5, 임시). 점프 시작의 역방향이 아닌 자연스러운 조절이 필요하며
**수치·곡선 자료는 사용자가 따로 제시한다.** 받으면 이 절을 갱신한다.

## 5. 애니메이션 선택 (3일차 구현 예정)

애니메이션 드라이버가 매 프레임 우선순위로 **다시 고른다**. 공격이 끝난 뒤 "복귀" 전이 코드는 없다.

```
사망 > 피격 > 공격(지상/공중) > 대시 > 이동(Idle·Run / Rise / Fall)
```
